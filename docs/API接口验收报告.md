# API 接口验收报告

## 1. 验收范围

- 验收日期：2026-08-22
- 后端分支：`feature/zcx-api-completion`
- 后端地址：`http://localhost:5113`
- Swagger：`http://localhost:5113/swagger`
- 数据库：Oracle Free 23ai（Docker，`FREEPDB1`）
- 对照文件：Apifox OpenAPI 导出、Swagger OpenAPI 导出、《功能点-v2》《开发流程》《GIT_API_数据库_代码质量规范》

## 2. 契约比对结论

- Apifox 共 81 个规范化接口操作，Swagger 共 115 个规范化接口操作。
- Apifox 中的 81 个接口在 Swagger 中全部存在，缺失数为 0。
- Swagger 额外提供 34 个增强接口，包括采购/销售/退货时间轴、采购退货、补货建议、供应商表现、日结、毛利排行和库存周转率等。
- `POST /sales` 同时兼容 Apifox 的 `details/saleQuantity` 请求结构和旧前端的 `items/quantity` 请求结构。
- 所有受保护业务接口均使用 JWT；管理员专属库存调整接口额外校验角色。

## 4. 实际测试结果

- 完整真实 HTTP 冒烟测试：77 项通过、0 项失败，覆盖 CRUD、JWT、RBAC、采购审批/入库、自动结算、POS、退货、积分、库存和统计。
- 采购驳回回归：`待审批 -> 已驳回 -> 修改 -> 待审批`，通过。
- 会员折扣回归：钻石会员商品金额 6.50 元，折扣 0.65 元，实付 5.85 元，通过。
- 组合优惠回归：钻石会员叠加 1 元满减券，商品金额 6.50 元，折扣 1.65 元，实付 4.85 元，通过。
- 优惠券事务回归：结算后状态为“已使用”并绑定销售单；销售作废后恢复“未使用”并解除绑定，通过。
- 日结归因回归：同一笔订单正确持久化并汇总会员折扣 0.65 元、优惠券抵扣 1.00 元，通过。
- 数据清理核验：测试单据和测试券残留为 0，商品 1 库存恢复 195，会员 2 积分/消费额/等级恢复种子值。
- 最终构建：0 个警告，0 个错误。

## 6. 扩展边界

- “买二送一”和独立促销时间窗尚无对应数据库规则表、Apifox 请求字段或前端选择入口，因此本次未凭空设计新协议；当前已覆盖数据库中实际存在的促销价、三类优惠券、会员折扣和积分规则。
- 供应商及时率当前业务口径为采购日期起 7 天内完成入库；若团队后续增加“约定到货日期”字段，应改为按约定日期统计。
- Apifox 共享项目尚未反向导入最新 Swagger；代码和 Swagger 已就绪，导入前应由项目成员确认覆盖策略，避免改坏共享接口示例。
